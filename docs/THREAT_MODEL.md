# Trust boundaries and risk register

NEXUS has two explicit profiles. Local mode trusts the operating-system user and loopback applications; it rejects non-loopback peers and non-loopback Host configuration. Server mode trusts authenticated accounts only within explicit membership. An administrator may create/disable/reset accounts but does not automatically read every workspace. Legacy ownership is never guessed. Roles: viewer reads/searches; editor also creates chats/sources and operates jobs; owner manages membership, model/index/retrieval policies, diagnostics, comparison and exports. Global legacy defaults require a server administrator.

| Boundary / risk | Implemented control | Residual risk / severity |
| --- | --- | --- |
| Direct object IDs / cross-user data | Middleware admission plus central Repository membership/role checks, SQL/vector filters, source/version checks; A/B tests across routes | Local machine compromise can read SQLite/originals. No at-rest encryption: medium for shared machines |
| Cookies / forged mutations | Random 256-bit session token, hashed server storage, expiry/logout/disable/reset revocation; HttpOnly/Secure/Strict cookies, session-bound CSRF, explicit Origin/CORS/Host checks | TLS termination and trusted proxy configuration remain operator responsibilities: high if misconfigured |
| Password guessing | scrypt n=131072/r=8/p=1, random salt, bounded password length, generic login errors/dummy KDF; peer-based login/request limits | No MFA, self-service recovery, account lockout or distributed limiter. Reverse-proxy perimeter limits required: medium |
| Untrusted files | MIME/signature/path/size/page limits, bounded DOCX/XML/ZIP, no archive path extraction; disposable parsing process/time cap; Unix process memory/CPU bounds | Windows parser is a process boundary, not an OS/network sandbox; native parser vulnerabilities remain medium/high for hostile public intake |
| Vault folder / link abuse | Explicit root CLI; reject symlinks/junctions/hardlinks/changing files; loopback API; no proxy env; external links/embeds never fetched | Malicious same-user directory-replacement races are outside a hardened filesystem sandbox: medium |
| Prompt injection | Evidence in user-data envelope, static trusted system policy, no agent tools or autonomous network/file actions; server citation validation | A real LLM may infer unsupported claims or follow malicious text. No immunity/entailment claim: medium |
| Provider SSRF / keys / cost | Fixed vendor destinations, exact allowlisted HTTPS custom origin, public-address DNS checks, literal-loopback Ollama, no redirects/env proxies; server-only keys; destination consent and paid operator/workspace gates | DNS rebinding between validation and connection remains possible for a malicious allowlisted operator endpoint; enforce egress firewall/approved DNS. Usage/cost outside NEXUS cannot be controlled: medium |
| Worker/index inconsistency | Durable SQL jobs/cursors, stable IDs, single-process OS lease, serialized index creation, versioned rebuild/coverage validation and rollback, immediate deletion revocation | Not distributed transactions across SQL/Chroma/files. Failures become visible/recoverable, not atomic multi-store snapshots: medium |
| Backup corruption / stale sessions | Stopped OS lease, WAL checkpoint, hash manifest, pre-write validation, new destination only, restore marker, SQL FK/integrity checks; sessions revoked | Backups contain private text and password hashes. Protect ACL/encryption/offsite copies yourself: medium |
| Logging / resource exhaustion | Route templates/status/opaque IDs only; local request/usage retention; no access-log query strings in provided scripts; 8 concurrent requests, bounded queues/fanout/context/output/timeout | One API process and peer limiter are not DDoS protection. Low disk can fail writes; diagnostics are best effort and use a short lock timeout: medium |

Security tests are regression evidence, not SOC2/GDPR/HIPAA certification or an external penetration test. Do not publish the local anonymous profile. Do not trust a reverse proxy to turn it into authenticated server mode. Use `NEXUS_PROFILE=server`, TLS, secure cookies, exact hosts/origins, restricted persistent volumes and a tested backup routine.

Primary design references: [OWASP sessions](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html), [OWASP CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html), [Python scrypt](https://docs.python.org/3/library/hashlib.html#hashlib.scrypt). These references inform implementation; they do not certify it.
