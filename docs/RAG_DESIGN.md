# Retrieval and citation rules

PDF extraction is page-based, one span per nonempty page. Image-only PDFs produce `needs_ocr`; mixed PDFs index readable text pages only (no claim of complete image coverage). Encrypted PDFs require an unlocked export. Empty/malformed files fail with an actionable state. UTF-8 text has one span; Markdown is split on ATX headings, with nested heading paths and basic fenced-code handling. Setext headings and full Markdown AST semantics are deferred.

Whitespace normalization stores a stable one-line span, strips null characters, and retains visible source content. Chunk offsets are **normalized-span character offsets**, not raw bytes/PDF coordinates. Source chunks are exact substrings verified again on retrieval. No pixel coordinates are fabricated.

LlamaIndex SentenceSplitter uses a character tokenizer to avoid hidden tokenizer downloads in offline mode. Defaults: 700 characters with 100-character overlap. This is a small-context choice for MiniLM's input window, not a promise against truncation in every language. Sentence boundaries are preferred. Query and passage embeddings are normalized on CPU in batches of eight. Hash mode exists solely for deterministic offline test/demo flows.

Phase 2 keyword search uses SQLite FTS5 unicode61 and BM25 over text/title/path/tag metadata. Terms and phrases are quoted FTS data in bound SQL parameters, never arbitrary SQL/FTS operators. Dense search uses the workspace's active compatible Chroma namespace. Hybrid deduplicates chunk IDs and sums weighted `1/(rrf_constant + rank)` contributions; ties use stable chunk IDs. Defaults: 15 candidates per stage, five final chunks, RRF constant 60, equal branch weights. Authorized document/vault/path/tag/type filters run consistently before both branches; SQL revalidates hits before context/diagnostics. Tags match any selected tag; other filters combine with AND.

The distance gate is a heuristic, not a calibrated sufficiency classifier. Context remains bounded by UTF-8 excerpt bytes (`context_budget`, default 4000), conservatively bounding excerpt token count; envelope/question are additional bounded inputs. Near-duplicate word sets and per-document caps prefer diverse passages. Optional cross-encoder ranking is lazy, off by default, CPU-only and cache-only unless the server permits model downloads. Unavailable reranking retains original rank with a diagnostic warning. BM25, cosine similarity and cross-encoder scores are named separately in diagnostic stages; final evidence score is RRF or reranker ranking, not a probability.

The generation adapter receives the locally reformulated standalone question and selected evidence. Short pronoun/follow-up questions can include the previous scoped user question; assistant/document text is not promoted into system instructions. Optional bounded local variants use original/reformulated/quoted-term queries. These paths make **zero additional cloud calls**. System instructions outrank untrusted data; no tools/filesystem access is granted. Cloud injection resistance cannot be proven by a mock test.

Citation IDs are generated on the server before generation. After generation, only cited IDs from the retrieved set survive; unknown `C…` markers reject the answer. An uncited generated answer is replaced with an insufficient-evidence response. A model may still make an unsupported inference from a valid cited excerpt: source linkage validates provenance, not entailment. No-evidence requests skip the provider and return an explicit insufficient-evidence answer.

All saved citations contain workspace_id, citation_id, document_id, document_version_id, chunk_id, source_span_id, title, page/heading, exact excerpt offsets and source URL; vault citations also include note_id/vault_id/path/tags. The source endpoint checks workspace/document/version/note/hash consistency. Retired-model chunks remain valid source references; changed/deleted note revisions are unavailable. The UI escapes all content, highlights exact normalized excerpts, and opens original PDFs with `#page=N`.

Index fingerprints include provider/model/revision, dimension, normalization, preprocessing/chunk configuration and the ONNX artifact where used. Rebuilds use isolated generation namespaces, persistent document/version checkpoints, SQL/vector parity checks and atomic activation. An older job cannot restore a pending changed note because note and document hashes must agree. Rollback is refused if current source coverage differs; deleting content also updates generation checkpoints. Old namespaces are not automatically purged.

Phase 1 uses a consistent **non-streaming** answer response with a visible pending state. SSE and provider token streaming are deferred; no simulated token stream is presented as real generation.
# Phase 3 control and evaluation

The preserved retrieval pipeline now runs behind authenticated workspace admission in server mode. A per-workspace model gateway applies exact provider/destination consent and call/output/timeout policies after retrieval; generation changes do not reindex. Model comparison reuses one evidence set and independently verifies both answers' citation IDs and current sources. Source identity/coverage remains distinct from claim entailment. OCR/DOCX source passages use real page/heading data only; DOCX has no fabricated pages. Text-only fallbacks never transmit images.

`examples/evaluation/release-cases.json` adds versioned controlled abstention, stale/deleted note, mixed-user and adversarial expectations alongside the fixed Phase 2 relevance labels. Release source checks measured three valid/cited IDs out of three and two controlled no-hit abstentions. These do not prove natural-language unsupported-question abstention or real LLM correctness. Request/retrieval/inference durations are observable; responses remain non-streaming and first-token latency is explicitly unavailable.
